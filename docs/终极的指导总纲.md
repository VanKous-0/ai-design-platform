# 1. 先定死几个关键结论

## 1.1 这个项目第一版不做什么
第一版**不做**：
- 不接真实外部 AI API
- 不做平台内直接生成图片 / 文本
- 不做微服务
- 不做 Redis / MQ / 分布式
- 不做复杂推荐算法
- 不做支付
- 不做复杂权限系统

## 1.2 这个项目第一版做什么
第一版必须做：
- 登录鉴权
- 工作流展示
- AI 工具测评中心
- 建筑设计提示词库
- 案例成果展示
- 上传对比复盘
- 首页内容 / 技术创新 / 获奖信息展示
- 后台管理接口

## 1.3 AI 工具测评模块的本质
这个模块第一版的本质是：

**工具测评 + 工具推荐 + 工具导航**

不是：
- 模型平台
- API 聚合平台
- 在线生成平台

所以第一版：
- 工具信息由管理员录入
- 测评分数由管理员录入
- 网页展示工具信息、评分、适用阶段、推荐理由
- 点击按钮跳转到工具官网或使用入口

# 2. 你的开发环境最终建议

## 2.1 IntelliJ IDEA 里需要什么
你现在主力用 **IJ（IntelliJ IDEA）**，这是正确的。

你应该这样配：

### 必须安装 / 启用
- **JetBrains AI Assistant**
- Maven 支持
- Spring 支持
- Lombok 支持（如果已经正常就不用折腾）

### 不建议安装
- **Codex Launcher**

原因：
- Codex 已经官方集成进 JetBrains IDE 的 AI Assistant
- 你不需要再额外装第三方 Codex Launcher
- 优先走官方集成路线，最稳

## 2.2 通义灵码要不要关
结论：

- **不用必须卸载**
- **不用必须关闭**
- 但建议：**先不要把它当主力**

推荐策略：
- 主力：**JetBrains AI Assistant + Codex**
- 备用：**通义灵码**
- 如果后面你发现：
  - 补全很乱
  - 面板太多
  - 快捷键冲突
  - IDE 变卡  
  那就把通义灵码先禁用

一句话：
**不是“冲突到不能用”，而是“同时开着容易乱”。**

## 2.3 JDK 21 能不能用
可以，没问题。

建议：
- 继续用 **JDK 21**
- Spring Boot 选 **3.x**
- 不需要为了教程多而强行降到 JDK 17

## 2.4 DataGrip 的定位
你的 DG（DataGrip）继续保留，非常合适。

它负责：
- 连接本地 MySQL
- 新建数据库
- 跑建表 SQL
- 跑初始化数据 SQL
- 查看表结构
- 执行查询语句

记住：
**数据库不是建在 IDEA 里，也不是建在 Cursor 里，而是建在你本机的 MySQL 服务里。**

# 4. 这个项目到底是什么

## 4.1 项目名称
**面向建筑设计全周期的生成式 AI 辅助决策服务平台**

## 4.2 项目定位
这是一个**网站平台**。

核心作用不是“自己生成内容”，而是把下面这些内容组织起来：
- 工作流
- 工具测评
- 提示词库
- 案例成果
- 复盘沉淀
- 展示内容

## 4.3 网站主流程
用户进入平台  
→ 选择设计阶段  
→ 查看标准工作流  
→ 查询推荐 AI 工具  
→ 查询/复制提示词  
→ 查看案例成果  
→ 上传自己的成果与复盘  
→ 平台沉淀内容并支持展示

# 9. 建表原则

## 9.1 通用字段
大多数表统一带：
- `id`
- `create_time`
- `update_time`
- `is_deleted`

按需增加：
- `status`
- `sort_order`
- `create_by`
- `update_by`

## 9.2 命名规则
- 表名：小写下划线
- 主键：`id`
- 外键：`xxx_id`
- 排序：`sort_order`
- 删除标记：`is_deleted`

## 9.3 设计约束
- 阶段与步骤拆表
- 工具与评分拆表
- 案例与资源拆表
- 复盘与附件拆表
- 多对多单独建关系表
- 不允许用逗号拼字符串表示关系

# 11. 开发规范

## 11.1 分层规范
每个模块都要分：
- entity
- dto
- vo
- mapper
- service
- service.impl
- controller

不要：
- 直接把 entity 当接口返回
- 直接把 entity 当请求入参

## 11.2 返回格式
统一：
- `code`
- `message`
- `data`

## 11.3 异常处理
必须有：
- 全局异常处理器
- 参数校验异常
- 业务异常
- 未授权异常

## 11.4 参数校验
必须用 Jakarta Validation。

常用注解：
- `@NotBlank`
- `@NotNull`
- `@Min`
- `@Max`
- `@Email`

## 11.5 文件上传
必须限制：
- 文件大小
- 文件类型
- 文件名重命名
- 本地目录保存

## 11.6 逻辑删除
优先逻辑删除，不轻易物理删除。

## 11.7 分页
列表接口支持分页。

## 11.8 排序
阶段、步骤、案例资源、首页内容等要有 `sort_order`。

## 11.9 API 文档
自动生成 OpenAPI / Knife4j 文档。
