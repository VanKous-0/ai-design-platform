# 后端项目总览

## 1. 项目定位

本项目是“AI 辅助建筑/景观设计流程管理与决策支持平台”的 Spring Boot 后端。

当前版本的核心定位是：

| 能力 | 说明 |
| --- | --- |
| AI 工具导航 | 维护 AI 工具信息、适用阶段、测评维度和推荐数据 |
| 工作流引导 | 将建筑/景观设计过程拆解为模板、节点、执行实例和步骤记录 |
| 提示词模板 | 按工具、工作流节点组织提示词，支持参数化渲染 |
| 使用记录 | 记录用户工作流执行、步骤输入输出、最近参数和行为日志 |
| 用户评价 | 支持普通用户对工具和工作流进行评分 |
| 数据统计 | 为内测、论文分析和验收提供后台统计接口 |
| 案例沉淀 | 支持案例展示、用户案例提交和管理员审核 |

当前版本不是一个直接调用大模型生成结果的系统，而是一个围绕“流程组织、提示词辅助、用户反馈、数据沉淀”的平台后端。

## 2. 当前版本功能范围

当前版本已经覆盖以下阶段能力：

| 阶段 | 已完成能力 |
| --- | --- |
| 基础展示型平台 | 登录 / JWT、用户基础模块、工作流阶段和步骤展示、AI 工具库、提示词库、案例展示、复盘模块、首页内容、统一返回体、全局异常、Knife4j/OpenAPI |
| 第一阶段 | `workflow_template`、`workflow_template_node`、`workflow_instance`、`workflow_step_record`、下一步提示、节点匹配提示词、参数化提示词渲染 |
| 第二阶段 | `user_profile`、`user_design_preference`、`user_recent_parameter`、`user_tool_rating`、`user_workflow_rating` |
| 第三阶段 | `usage_event`、`survey_feedback`、后台统计接口 |
| 第四阶段 A | 普通用户提交案例、用户管理自己的案例、用户添加案例资源 URL、管理员审核通过 / 驳回、公开案例接口只展示 `APPROVED` 案例 |

## 3. 当前版本不做的内容

当前版本明确不做以下内容：

| 不做内容 | 当前处理方式 |
| --- | --- |
| 真实外部 AI API 调用 | 平台只提供提示词模板、参数化渲染和流程记录 |
| OpenAI、DeepSeek、通义、豆包、Kimi、ChatGPT 等模型接口 | 当前未接入，后续可扩展统一 AI 调用层 |
| API Key 配置 | 当前未实现，避免密钥泄露和部署复杂度 |
| 模型调用 Service | 当前未实现 |
| token 计费 | 当前未实现 |
| 流式输出 | 当前未实现 |
| 真实文件上传 | 当前只保存资源 URL |
| `MultipartFile` 文件保存 | 当前未实现 |
| 云存储 | 当前未实现 |
| 视频上传和转码 | 当前未实现 |
| 大文件处理 | 当前未实现 |

案例资源、图片资源、视频资源当前只保存 URL。

AI 生成行为由用户复制平台生成的提示词，到外部 AI 工具中完成。平台负责流程组织、提示词模板、参数化渲染、过程记录、评价反馈和统计分析。

## 6. 用户角色

| 角色 | 权限范围 |
| --- | --- |
| 匿名用户 | 浏览公开展示接口，提交匿名行为日志和问卷反馈 |
| 普通用户 `USER` | 登录后管理个人资料、设计偏好、最近参数、工作流实例、评分和自己的案例 |
| 管理员 `ADMIN` | 访问 `/api/admin/**`，维护后台数据、审核案例、查看统计 |

## 7. 后端整体分层

项目整体遵循典型 Spring Boot 分层结构：

| 层级 | 说明 |
| --- | --- |
| `controller` | 接收 HTTP 请求，做参数校验，统一返回 `Result.success(data)` |
| `service` | 定义业务接口 |
| `service.impl` | 实现业务逻辑、权限校验、状态流转和数据组装 |
| `mapper` | MyBatis-Plus 数据访问 |
| `entity` | 数据库表映射对象，不直接返回前端 |
| `dto` | 请求参数对象 |
| `vo` | 前端响应对象 |
| `common` | 统一返回、异常、安全、JWT、OpenAPI 等公共能力 |

## 8. 当前版本能力总结

当前版本已经从“展示型后端”升级为“可执行、可记录、可评价、可统计、可沉淀案例”的平台后端。

核心闭环如下：

1. 用户登录平台。
2. 选择工作流模板。
3. 创建工作流执行实例。
4. 在节点中选择匹配提示词。
5. 根据参数渲染完整提示词。
6. 用户复制提示词到外部 AI 工具完成生成。
7. 用户将结果粘贴回平台并完成节点。
8. 系统返回下一步提示。
9. 用户提交评分和案例。
10. 管理员查看统计数据，并审核用户案例。

当前版本以“流程组织和数据闭环”为重点，为后续接入真实 AI API、对象存储、视频中心和可视化分析预留了扩展空间。
