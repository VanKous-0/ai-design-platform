# 核心业务流程说明

## A. 工作流执行流程

工作流执行是当前平台的核心闭环。

### 流程步骤

1. 用户进入工作流页面。
2. 前端调用 `GET /api/workflow-templates` 查询可用模板。
3. 用户选择某一套模板。
4. 前端调用 `GET /api/workflow-templates/{id}` 查看模板节点。
5. 用户点击开始。
6. 前端调用 `POST /api/workflow-instances` 创建执行实例。
7. 用户进入当前节点。
8. 前端调用 `GET /api/prompts/by-node?nodeId=xxx` 查询节点匹配提示词。
9. 用户选择提示词。
10. 前端调用 `GET /api/prompts/{id}/parameters` 获取参数定义。
11. 用户填写参数。
12. 前端调用 `POST /api/prompts/{id}/render` 获取完整提示词。
13. 用户复制提示词到外部 AI 工具中生成结果。
14. 用户将外部 AI 工具返回结果粘贴回平台。
15. 前端调用 `POST /api/workflow-instances/{id}/steps/{nodeId}/complete` 完成节点。
16. 后端返回下一步提示：
    - `nextNodeId`
    - `nextNodeName`
    - `nextTip`
    - `whetherFinished`
17. 用户继续完成后续节点。
18. 所有节点完成后，工作流实例结束。

### 当前边界

| 项目 | 当前实现 |
| --- | --- |
| AI 生成 | 用户复制提示词到外部 AI 工具完成 |
| 平台职责 | 模板组织、参数渲染、过程记录、下一步提示 |
| 是否调用外部 AI API | 当前未实现 |
| 是否保存每步输入输出 | 保存到 `workflow_step_record` |

## B. 参数化提示词流程

参数化提示词用于把模板中的 `{paramKey}` 替换成用户填写的值。

### 流程步骤

1. 前端根据当前工作流节点调用 `GET /api/prompts/by-node?nodeId=xxx`。
2. 用户从下拉菜单选择提示词。
3. 前端调用 `GET /api/prompts/{id}/parameters`。
4. 后端返回参数定义，例如：
   - `paramKey`
   - `paramName`
   - `paramType`
   - `required`
   - `defaultValue`
   - `placeholder`
   - `sortOrder`
5. 前端结合用户设计偏好和最近参数做自动回填：
   - `GET /api/user/preferences`
   - `GET /api/user/recent-parameters`
6. 用户确认参数。
7. 前端调用 `POST /api/prompts/{id}/render`。
8. 后端对 `prompt_template.content` 中的 `{paramKey}` 做简单字符串替换。
9. 后端返回 `renderedContent`。
10. 用户复制 `renderedContent` 到外部 AI 工具。

### 渲染规则

| 规则 | 说明 |
| --- | --- |
| 占位符格式 | `{projectType}`、`{area}`、`{style}` |
| 替换方式 | 简单字符串替换 |
| 多余参数 | 忽略 |
| 必填参数缺失 | 返回业务异常 |
| 表达式执行 | 不支持 |
| 脚本执行 | 不支持 |

## C. 用户评分流程

用户评分用于收集普通用户真实反馈，和管理员维护的专业测评分离。

### 工具评分

1. 用户使用某个 AI 工具。
2. 前端调用 `POST /api/ratings/tools` 提交评分。
3. 评分维度包括：
   - `effectScore`
   - `easeScore`
   - `stabilityScore`
   - `recommendScore`
   - `comment`
4. 同一用户对同一工具重复提交时更新原评分。
5. 前端可调用 `GET /api/ratings/tools/summary?toolId=xxx` 查看公开平均分。
6. 后台统计接口可汇总工具评分。

### 工作流评分

1. 用户完成或体验某次工作流实例。
2. 前端调用 `POST /api/ratings/workflows` 提交评分。
3. `instanceId` 必须属于当前登录用户。
4. `templateId` 需要和实例所属模板一致。
5. 同一用户对同一实例重复提交时更新原评分。
6. 前端可调用：
   - `GET /api/ratings/workflows/summary?templateId=xxx`
   - `GET /api/ratings/workflows/summary?instanceId=xxx`

### 数据区分

| 表 | 数据来源 | 用途 |
| --- | --- | --- |
| `ai_tool_evaluation` | 管理员维护 | 专业测评 |
| `user_tool_rating` | 普通用户提交 | 真实使用反馈 |
| `user_workflow_rating` | 普通用户提交 | 工作流体验反馈 |

## D. 行为日志与统计流程

行为日志为论文分析、内测反馈和项目验收提供数据支撑。

### 前端埋点流程

1. 用户浏览、点击、复制、渲染提示词或完成节点。
2. 前端调用 `POST /api/usage-events`。
3. 匿名用户传 `anonymousId`。
4. 登录用户请求头携带 token，后端尽量记录 `userId`。
5. 后端保存事件到 `usage_event`。
6. 仅当登录用户执行映射了明确 `preferenceHints` 的 `render_prompt` 时，
   后端才在同一事务中更新 `BEHAVIOR_INFERRED` 聚合画像。

`usage_event` 保存原始行为事实，`user_preference_signal` 只保存当前聚合画像，
Workflow iteration 的 `profile_context_snapshot` 保存某次执行实际使用的服务端画像。
匿名、复制、浏览、登录、停留时长和没有明确映射的事件都不会更新长期画像。

### 事件字段

| 字段 | 说明 |
| --- | --- |
| `eventType` | 行为类型，例如 `view`、`click`、`copy_prompt`、`render_prompt` |
| `targetType` | 目标类型，例如 `prompt`、`tool`、`workflow_template` |
| `targetId` | 目标数据 ID，可为空 |
| `pageUrl` | 页面路径 |
| `stayDuration` | 停留时长，单位秒 |
| `inputSummary` | 简短输入摘要 |
| `extraJson` | 扩展字段，只按字符串保存 |
| `preferenceEvidenceJson` | 服务端解析并随事件保存的结构化偏好证据，客户端不能直接提交 |

### 后台统计流程

管理员登录后可访问：

| 接口 | 用途 |
| --- | --- |
| `/api/admin/statistics/usage-summary` | 行为总览 |
| `/api/admin/statistics/event-type-summary` | 按事件类型统计 |
| `/api/admin/statistics/target-type-summary` | 按目标类型统计 |
| `/api/admin/statistics/prompt-summary` | 提示词复制和渲染统计 |
| `/api/admin/statistics/workflow-summary` | 工作流实例和完成情况统计 |
| `/api/admin/statistics/tool-rating-summary` | 工具评分汇总 |
| `/api/admin/statistics/workflow-rating-summary` | 工作流评分汇总 |

## E. 用户案例审核流程

用户案例审核保证公开案例内容可控。

### 提交流程

1. 用户登录。
2. 前端调用 `POST /api/user/cases` 提交案例表单。
3. 后端从 token 获取 `userId`。
4. 案例保存到 `case_project`。
5. 新案例默认：

```text
audit_status = PENDING
```

6. 此时案例不会出现在公开接口中。

### 资源 URL 流程

1. 用户在自己的案例下添加资源。
2. 前端调用 `POST /api/user/cases/{id}/assets`。
3. 后端只保存 `assetUrl` 字符串。
4. 不进行真实文件上传。
5. 不保存本地文件。
6. 不接入云存储。

### 审核流程

1. 管理员访问 `GET /api/admin/cases/pending` 查看待审核案例。
2. 管理员通过：

```http
POST /api/admin/cases/{id}/approve
```

3. 案例变为：

```text
audit_status = APPROVED
```

4. 公开接口可以查询该案例。
5. 管理员驳回：

```http
POST /api/admin/cases/{id}/reject
```

6. 案例变为：

```text
audit_status = REJECTED
```

7. 公开接口不可见。

### 公开过滤规则

公开案例接口只返回：

```text
status = 1
is_deleted = 0
audit_status = APPROVED
```

涉及接口：

- `GET /api/cases`
- `GET /api/cases/{id}`
- `GET /api/cases/{id}/assets`
- `GET /api/cases/recommend`

`case_asset` 不单独加审核字段，资源是否公开完全依赖所属 `case_project.audit_status`。
