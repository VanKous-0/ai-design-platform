# 数据库脚本执行顺序（历史参考）

> 当前运行时唯一 schema 来源是 `src/main/resources/db/migration` 下的
> Flyway migration。新建空库不得再手工执行本页列出的 `sql/*.sql`；Docker
> Compose 也已移除该初始化路径。下列顺序仅用于审计版本 26 之前的历史数据库。

空库由 Flyway 先执行 `V1__legacy_schema_and_seed_baseline.sql`，再顺序执行
`V27` 及之后的 migration。已有非空旧库继续以版本 26 baseline 后升级，
因此不会重复执行 V1。

## 1. 总体原则

历史脚本曾按“基础表 -> 基础初始化数据 -> 业务模块表 -> 增量增强表”的顺序执行。

执行前请确认当前分支和后端代码版本一致。若数据库缺少后端代码中已经使用的字段，启动或访问接口时可能出现 SQL 错误。

特别注意：

`case_audit_schema.sql` 需要在新版后端启动前执行。否则公开案例接口按 `audit_status` 过滤时，可能因为 `case_project.audit_status` 字段不存在而报错。

## 2. 推荐执行顺序

| 顺序 | 脚本 | 类型 | 说明 |
| --- | --- | --- | --- |
| 1 | `sql/schema.sql` | 建表 | 基础用户表和公共基础表，至少应包含 `sys_user` |
| 2 | `sql/init_data.sql` | 初始化数据 | 初始化管理员账号和基础数据 |
| 3 | `sql/workflow_schema.sql` | 建表 | 传统工作流阶段和步骤：`workflow_stage`、`workflow_step` |
| 4 | `sql/workflow_init_data.sql` | 初始化数据 | 初始化展示型工作流阶段和步骤 |
| 5 | `sql/ai_tool_schema.sql` | 建表 | AI 工具、阶段关系、测评维度和专业测评表 |
| 6 | `sql/ai_tool_init_data.sql` | 初始化数据 | 初始化 AI 工具库和测评数据 |
| 7 | `sql/prompt_schema.sql` | 建表 | 提示词模板和工具关系：`prompt_template`、`prompt_tool_rel` |
| 8 | `sql/prompt_init_data.sql` | 初始化数据 | 初始化提示词模板 |
| 9 | `sql/case_schema.sql` | 建表 | 案例主表和资源表：`case_project`、`case_asset` |
| 10 | `sql/case_init_data.sql` | 初始化数据 | 初始化公开案例 |
| 11 | `sql/review_schema.sql` | 建表 | 复盘记录和复盘资源 |
| 12 | `sql/review_init_data.sql` | 初始化数据 | 初始化复盘内容 |
| 13 | `sql/site_schema.sql` | 建表 | 首页内容和获奖记录 |
| 14 | `sql/site_init_data.sql` | 初始化数据 | 初始化首页展示内容 |
| 15 | `sql/workflow_runtime_schema.sql` | 建表 | 工作流模板、节点、实例、步骤执行记录 |
| 16 | `sql/workflow_runtime_init_data.sql` | 初始化数据 | 初始化多套典型工作流模板和节点 |
| 17 | `sql/prompt_enhance_schema.sql` | 建表 | 节点提示词关系和提示词参数表 |
| 18 | `sql/prompt_enhance_init_data.sql` | 初始化数据 | 初始化节点与提示词关系、参数定义 |
| 19 | `sql/user_profile_schema.sql` | 建表 | 用户资料、设计偏好、最近参数 |
| 20 | `sql/user_profile_init_data.sql` | 初始化数据 | 可初始化普通测试账号 `testuser` |
| 21 | `sql/rating_schema.sql` | 建表 | 用户工具评分和工作流评分 |
| 22 | `sql/rating_init_data.sql` | 初始化数据 | 可选评分演示数据 |
| 23 | `sql/statistics_schema.sql` | 建表 | 行为日志和问卷反馈 |
| 24 | `sql/statistics_init_data.sql` | 初始化数据 | 可为空或写说明注释 |
| 25 | `sql/case_audit_schema.sql` | 表结构扩展 | 为 `case_project` 增加审核字段和索引 |
| 26 | `sql/case_audit_init_data.sql` | 初始化数据 | 可为空或写说明注释 |
| 27 | `src/main/resources/db/migration/V27__experiment_support.sql` | Flyway 迁移 | 增加实验编号、分组、批次和索引 |

## 3. 脚本依赖说明

| 脚本 | 依赖 |
| --- | --- |
| `workflow_runtime_schema.sql` | 依赖基础用户表；节点可选关联 `workflow_stage`、`workflow_step` |
| `workflow_runtime_init_data.sql` | 如果关联旧阶段和步骤，需要先执行 `workflow_init_data.sql` |
| `prompt_enhance_schema.sql` | 依赖 `prompt_template` 和 `workflow_template_node` |
| `prompt_enhance_init_data.sql` | 依赖已有提示词和工作流节点数据 |
| `user_profile_schema.sql` | 依赖 `sys_user` |
| `rating_schema.sql` | 依赖 `sys_user`、`ai_tool`、`workflow_template`、`workflow_instance` |
| `statistics_schema.sql` | 可独立建表，但统计接口会读取提示词、工作流、评分等表 |
| `case_audit_schema.sql` | 必须在 `case_project` 已存在后执行 |

## 4. 重复执行注意事项

| 类型 | 注意事项 |
| --- | --- |
| 基础建表脚本 | 如果未使用 `IF NOT EXISTS`，重复执行前需要确认表是否已存在 |
| 初始化脚本 | 如果脚本使用固定主键，重复执行可能主键冲突 |
| 普通测试账号 | 如果 `sys_user.username` 有唯一约束，应使用 `INSERT IGNORE` 或 `ON DUPLICATE KEY UPDATE` |
| 增量 `ALTER TABLE` 脚本 | MySQL 版本不同，字段存在性判断能力不同；重复执行前需确认字段是否已存在 |
| 唯一索引 | 重复创建唯一索引可能失败，执行前需检查索引名 |

## 5. `case_audit_schema.sql` 特别说明

该脚本应为 `case_project` 增加：

| 字段 | 说明 |
| --- | --- |
| `submit_user_id` | 普通用户提交人 ID |
| `audit_status` | 审核状态：`PENDING`、`APPROVED`、`REJECTED` |
| `audit_comment` | 审核意见 |
| `audit_time` | 审核时间 |
| `auditor_id` | 审核管理员 ID |

历史已有案例应默认 `audit_status = 'APPROVED'`，避免原有公开案例突然查不到。

公开案例接口会过滤：

```sql
status = 1
AND is_deleted = 0
AND audit_status = 'APPROVED'
```

因此该脚本必须在部署新版后端前执行。

## 6. 建议环境执行策略

| 环境 | 建议 |
| --- | --- |
| 本地开发 | 可按完整顺序从空库执行 |
| 测试环境 | 先备份数据库，再执行新增 schema 和 init 脚本 |
| 已有演示环境 | 不建议清库；只执行缺失的增量脚本 |
| 生产或答辩演示环境 | 先在测试库验证脚本，再执行到正式库 |

## 7. Flyway 与管理员初始化

- 历史 26 个脚本执行完后，应用会将现有数据库 baseline 为版本 26，并自动执行 V27。
- 不要手工先执行 V27 后再让 Flyway执行，否则会重复增加字段。
- 仓库不再保存固定管理员密码。首次启动通过 `ADMIN_BOOTSTRAP_USERNAME` 和 `ADMIN_BOOTSTRAP_PASSWORD` 创建管理员，创建后应从运行环境移除管理员初始密码。
