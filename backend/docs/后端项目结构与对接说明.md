# 后端项目结构与对接说明

本文档基于当前仓库代码、`docs/` 说明文档、`sql/` 建表与初始化脚本整理。若旧文档和代码存在差异，以当前代码实际实现为准。

当前已确认的差异点：

- `docs/` 中目前没有单独的第六阶段复盘模块详细说明文档，但 `src/main/java/com/project/modules/review`、`sql/review_schema.sql`、`sql/review_init_data.sql` 已经实现复盘模块。
- 总纲中曾设想复盘有普通用户上传接口，例如 `POST /api/reviews`、`GET /api/reviews/my`。当前代码实际实现是：复盘前台接口只做公开查询，新增/修改/删除复盘在 `/api/admin/reviews` 下完成，并要求管理员 token。
- 部分文档提到后台可能需要列表接口，但当前大多数后台模块只实现新增、修改、删除、关系设置，没有单独的后台查询列表接口。后台查看数据时可先用公开查询接口看启用数据，或直接查数据库。

## 一、项目整体结构总览

### 1. 项目定位

本项目是“AI 辅助建筑设计决策平台”的 Spring Boot 后端。第一版不直接接入外部 AI API，不在后端调用豆包、DeepSeek、通义、Kimi、ChatGPT 等模型生成内容，而是做一个可维护、可展示、可对接前端的平台后端。

它的核心价值是把建筑设计过程中的流程、工具、提示词、案例、复盘、首页展示内容组织起来，让前端能稳定读取，管理员能维护基础数据。

### 2. 当前后端模块

| 模块 | 代码目录 | 主要作用 |
| --- | --- | --- |
| 登录 / JWT / 用户基础模块 | `modules.auth`、`modules.user`、`common.config` | 登录校验、生成 JWT、获取当前用户、控制后台接口权限 |
| 工作流模块 | `modules.workflow` | 维护建筑设计阶段和阶段下步骤，是全平台业务主线 |
| AI 工具测评模块 | `modules.tool` | 维护 AI 工具、适用阶段、测评维度和评分，用于工具推荐和导航 |
| 提示词库模块 | `modules.prompt` | 按阶段和分类管理提示词，并关联推荐工具 |
| 案例成果展示模块 | `modules.caseproject` | 展示案例、案例所属阶段、主要工具和案例资源 |
| 复盘模块 | `modules.review` | 管理复盘记录和附件，按阶段/工具展示经验沉淀 |
| 首页内容模块 | `modules.site` | 管理首页区块、首页聚合数据、获奖/成果记录 |
| 公共基础能力 | `common` | 统一返回体、全局异常处理、JWT 过滤器、安全配置、OpenAPI 配置 |

### 3. 模块之间的关系

工作流模块是业务骨架。`workflow_stage` 表里的阶段会被工具、提示词、案例、复盘引用：

```text
workflow_stage
  -> workflow_step
  -> ai_tool_stage_rel -> ai_tool
  -> prompt_template -> prompt_tool_rel -> ai_tool
  -> case_project -> case_asset
  -> review_record -> review_asset
```

首页模块不强依赖其他业务表，它通过 `site_content` 配置首页区块，通过 `award_record` 展示成果记录。前端首页也可以用首页入口跳转到工作流、工具、提示词、案例、复盘页面。

登录/JWT 模块横向服务所有后台接口。公开展示接口通常不需要 token；`/api/admin/**` 接口需要登录，并且 Controller 上使用 `@PreAuthorize("hasRole('ADMIN')")` 限制管理员访问。

### 4. 主业务链路和内容展示链路

主业务链路：

1. 工作流：先定义建筑设计阶段和步骤。
2. AI 工具测评：围绕阶段推荐可用工具。
3. 提示词库：围绕阶段和工具提供可复制提示词。
4. 案例展示：展示某阶段、某工具的案例成果。
5. 复盘沉淀：记录项目经验、问题、解决方案和附件。

内容展示链路：

1. 首页内容：平台介绍、模块入口、联系方式、图片路径、链接。
2. 获奖/成果：获奖记录、成果说明、图片和链接。
3. 案例资源、复盘附件：为案例和复盘提供图片或文件 URL。

### 5. 用户视角的完整流程

普通访问者进入平台后，典型流程是：

1. 打开首页，前端请求 `GET /api/site/home` 获取首页聚合数据。
2. 查看设计阶段，前端请求 `GET /api/stages`。
3. 进入某个阶段，查看阶段详情 `GET /api/stages/{id}` 和步骤 `GET /api/stages/{id}/steps`。
4. 查看该阶段推荐 AI 工具，调用 `GET /api/tools/recommend?stageId=...`。
5. 查看提示词，调用 `GET /api/prompts?stageId=...` 或 `GET /api/prompts/recommend?stageId=...&toolId=...`。
6. 查看案例，调用 `GET /api/cases?stageId=...` 或案例详情接口。
7. 查看复盘经验，调用 `GET /api/reviews?stageId=...` 或复盘详情接口。

管理员维护内容时，先调用 `POST /api/auth/login` 获取 token，再把请求头设置为：

```http
Authorization: Bearer <accessToken>
```

然后调用 `/api/admin/**` 下的新增、修改、删除接口。

## 二、项目目录结构

### 1. 根目录

| 目录或文件 | 作用 |
| --- | --- |
| `src/main/java/com/project` | Java 后端主代码 |
| `src/main/resources` | Spring Boot 配置、Mapper XML 目录、静态资源目录 |
| `sql` | 建表 SQL 和初始化数据 SQL |
| `docs` | 项目总纲、阶段说明和本文档 |
| `pom.xml` | Maven 依赖和构建配置 |

### 2. `src/main/java/com/project`

这是后端 Java 包根目录。当前包含：

- `ProjectApplication.java`：Spring Boot 启动类。
- `common`：公共配置、返回体、异常、工具类。
- `modules`：业务模块，每个模块按分层结构组织。

### 3. `common`

`common` 保存所有模块共用的能力：

| 子目录 | 作用 |
| --- | --- |
| `config` | `SecurityConfig`、`JwtAuthenticationFilter`、`JwtProperties`、`OpenApiConfig` |
| `exception` | `BusinessException`、`UnauthorizedException`、`GlobalExceptionHandler` |
| `result` | `Result`、`ResultCode` 统一返回结构 |
| `util` | `JwtUtil` 生成和解析 JWT |

重点文件：

- `SecurityConfig`：决定哪些接口公开、哪些接口需要登录。
- `JwtAuthenticationFilter`：从 `Authorization: Bearer xxx` 中解析 token，写入 Spring Security 上下文。
- `OpenApiConfig`：决定 Knife4j/OpenAPI 文档中哪些接口显示锁、哪些接口不显示锁。
- `Result`：所有接口统一返回 `{ code, message, data }`。
- `GlobalExceptionHandler`：统一处理业务异常、参数校验异常、401、403 和系统异常。

### 4. `modules`

`modules` 下是业务模块。当前模块如下：

```text
modules
├── auth
├── user
├── workflow
├── tool
├── prompt
├── caseproject
├── review
└── site
```

每个业务模块基本都按以下结构组织：

| 分层 | 作用 |
| --- | --- |
| `controller` | 接收前端 HTTP 请求，定义 URL、请求方式、参数入口 |
| `service` | 业务接口，定义模块能力 |
| `service.impl` | 业务实现，写校验、查询、组装返回结果 |
| `mapper` | MyBatis-Plus 数据库访问接口，通常继承 `BaseMapper<Entity>` |
| `entity` | 数据库表对应的 Java 对象 |
| `dto` | 请求体对象，接收前端传入字段，并做参数校验 |
| `vo` | 返回给前端的对象，控制接口返回字段 |

### 5. `mapper`

当前项目的 Mapper 在各模块内，例如：

- `modules.workflow.mapper.WorkflowStageMapper`
- `modules.tool.mapper.AiToolMapper`
- `modules.prompt.mapper.PromptTemplateMapper`

这些 Mapper 基本使用 MyBatis-Plus 的 `BaseMapper`，没有大量 XML SQL。`src/main/resources/mapper` 目前只有 `.gitkeep`，表示保留 XML Mapper 目录，但当前主要不是靠 XML 写 SQL。

### 6. `resources`

`src/main/resources/application.yml` 是核心配置：

- 服务端口：`8080`
- 数据库：`ai_design_platform`
- 数据库用户：`root`
- MyBatis-Plus：开启下划线转驼峰、逻辑删除字段 `isDeleted`
- JWT：请求头 `Authorization`、前缀 `Bearer`、有效期 `86400` 秒
- Knife4j / Springdoc：开启接口文档
- 日志：`com.project` 为 debug

注意：`application.yml` 当前包含本地数据库密码，适合本地开发。正式部署时应改为环境变量或安全配置。

### 7. `sql`

`sql` 保存数据库脚本：

| 文件 | 作用 |
| --- | --- |
| `schema.sql` | 创建 `sys_user` |
| `init_data.sql` | 初始化管理员账号 `admin/admin123` |
| `workflow_schema.sql`、`workflow_init_data.sql` | 工作流表和初始阶段/步骤 |
| `ai_tool_schema.sql`、`ai_tool_init_data.sql` | AI 工具、阶段关系、测评维度、评分 |
| `prompt_schema.sql`、`prompt_init_data.sql` | 提示词、提示词-工具关系 |
| `case_schema.sql`、`case_init_data.sql` | 案例、案例资源 |
| `review_schema.sql`、`review_init_data.sql` | 复盘、复盘附件 |
| `site_schema.sql`、`site_init_data.sql` | 首页内容、获奖记录 |

### 8. `docs`

`docs` 保存项目设计说明。当前有总纲、第二/三/四/五/七阶段说明，缺少第六阶段复盘详细说明，但代码和 SQL 中已有复盘模块。

## 三、一次请求的后端流转

以前端请求 `GET /api/tools?stageId=1` 为例：

1. 请求进入 Spring Boot。
2. `SecurityConfig` 判断该路径是公开 GET 接口，允许匿名访问。
3. 请求进入 `AiToolController.listTools`。
4. Controller 把 `stageId`、`keyword` 传给 `AiToolService`。
5. `AiToolServiceImpl` 校验阶段是否存在并启用。
6. Service 调用 `AiToolStageRelMapper` 查适用该阶段的工具 ID。
7. Service 调用 `AiToolMapper` 查启用的工具。
8. Service 组装 `AiToolVO`，补充适用阶段列表。
9. Controller 用 `Result.success(data)` 包装返回。
10. 前端拿到统一 JSON：`code`、`message`、`data`。

后台请求多一步鉴权。以前端请求 `POST /api/admin/tools` 为例：

1. 请求头必须带 `Authorization: Bearer <token>`。
2. `JwtAuthenticationFilter` 解析 token，得到用户 ID 和角色。
3. `SecurityConfig` 要求该请求必须登录。
4. Controller 上的 `@PreAuthorize("hasRole('ADMIN')")` 要求角色是 `ADMIN`。
5. 通过后才进入 Controller 和 Service。

## 四、DTO、Entity、VO 的使用方式

### 1. DTO

DTO 是请求对象，主要用于新增、修改、设置关系等写操作。例如：

- `AiToolCreateRequest`
- `PromptCreateRequest`
- `CaseProjectUpdateRequest`
- `ReviewRecordCreateRequest`
- `SiteContentCreateRequest`

DTO 上常见校验：

- `@NotBlank`：字符串不能为空。
- `@NotNull`：对象不能为空。
- `@Min`：数值不能低于指定值。
- `@DecimalMin`、`@DecimalMax`：评分范围校验。

前端传 JSON 时字段使用驼峰命名，例如 `stageId`、`sortOrder`、`officialUrl`。

### 2. Entity

Entity 对应数据库表。例如：

- `WorkflowStage` 对应 `workflow_stage`
- `AiTool` 对应 `ai_tool`
- `PromptTemplate` 对应 `prompt_template`
- `CaseProject` 对应 `case_project`

Entity 主要用于数据库读写，不建议直接作为接口返回给前端。当前项目大多数接口都在 Service 中把 Entity 转成 VO。

### 3. VO

VO 是返回给前端的数据结构。例如：

- `AiToolVO`
- `PromptDetailVO`
- `CaseProjectDetailVO`
- `ReviewRecordDetailVO`
- `HomeVO`

如果前端说“接口里少字段”，通常应该改 VO 和 Service 的组装逻辑，而不是直接把 Entity 暴露出去。

### 4. 常见修改应该改哪里

| 目标 | 主要修改位置 |
| --- | --- |
| 改接口路径或请求方式 | Controller |
| 改请求字段 | DTO、Controller、Service |
| 改返回字段 | VO、Service 的 `toXXXVO` 方法 |
| 改数据库字段 | SQL schema、Entity、DTO/VO、Service |
| 改查询条件 | Service 中的 `LambdaQueryWrapper` |
| 改权限是否需要 token | `SecurityConfig`、`OpenApiConfig`、Controller 上的 `@PreAuthorize` |

## 五、按模块讲解

### 1. 登录 / JWT 模块

作用：负责管理员和用户登录、生成 JWT、获取当前用户信息。

数据库表：`sys_user`。

主要接口：

| 接口 | 方法 | token | 说明 |
| --- | --- | --- | --- |
| `/api/auth/login` | POST | 不需要 | 登录，返回 token 和用户信息 |
| `/api/user/me` | GET | 需要 | 根据 token 获取当前用户 |

关键请求字段：

- 登录：`username`、`password`

关键返回字段：

- `tokenType`：当前为 `Bearer`
- `accessToken`：JWT token
- `expiresIn`：有效期秒数
- `user.id`、`user.username`、`user.nickname`、`user.role`

最重要字段：

- `sys_user.username`：登录名，唯一。
- `sys_user.password_hash`：密码，支持 Spring Security PasswordEncoder 格式，例如 `{noop}admin123`。
- `sys_user.role`：`ADMIN` 才能访问后台管理接口。
- `sys_user.status`：禁用用户不能登录或获取当前用户。

容易混淆点：

- token 不是只填 JWT 字符串，必须带前缀：`Bearer <accessToken>`。
- Spring Security 判断管理员角色时使用 `ROLE_ADMIN`，但数据库里存的是 `ADMIN`，过滤器会自动加 `ROLE_`。
- `/api/user/me` 需要 token；`/api/auth/login` 不需要。

### 2. 工作流模块

作用：维护建筑设计阶段和阶段下的步骤，是其他模块的业务主线。

数据库表：

- `workflow_stage`
- `workflow_step`

前台接口：

| 接口 | 方法 | token | 说明 |
| --- | --- | --- | --- |
| `/api/stages` | GET | 不需要 | 查询启用阶段列表 |
| `/api/stages/{id}` | GET | 不需要 | 查询启用阶段详情 |
| `/api/stages/{id}/steps` | GET | 不需要 | 查询某阶段启用步骤 |

后台接口：

| 接口 | 方法 | token | 说明 |
| --- | --- | --- | --- |
| `/api/admin/stages` | POST | ADMIN | 新增阶段 |
| `/api/admin/stages/{id}` | PUT | ADMIN | 修改阶段 |
| `/api/admin/stages/{id}` | DELETE | ADMIN | 逻辑删除阶段，并删除该阶段下步骤 |
| `/api/admin/steps` | POST | ADMIN | 新增步骤 |
| `/api/admin/steps/{id}` | PUT | ADMIN | 修改步骤 |
| `/api/admin/steps/{id}` | DELETE | ADMIN | 逻辑删除步骤 |

关键字段：

- `workflow_stage.name`：阶段展示名称。
- `workflow_stage.code`：阶段稳定编码，唯一。
- `workflow_stage.description`：阶段说明。
- `workflow_stage.sort_order`：阶段排序。
- `workflow_stage.status`：是否前台展示。
- `workflow_step.stage_id`：步骤所属阶段。
- `workflow_step.title`、`content`、`input_desc`、`output_desc`、`tips`：步骤展示内容。

展示内容怎么改：

- 改阶段名、说明、步骤内容：优先改数据库或调用后台接口。
- 改返回字段结构：改 VO 和 Service。
- 改阶段/步骤表结构：改 SQL、Entity、DTO、VO、Service。

容易混淆点：

- `stage` 是大阶段，例如“概念设计”；`step` 是阶段下具体步骤，例如“设计概念生成”。
- `id` 不是业务顺序，展示顺序看 `sort_order`。
- 删除是逻辑删除，数据库记录仍在，但 `is_deleted = 1`。

### 3. AI 工具测评模块

作用：展示 AI 工具信息、适用阶段、维度评分和推荐关系。当前不调用外部 AI API。

数据库表：

- `ai_tool`
- `ai_tool_stage_rel`
- `evaluation_dimension`
- `ai_tool_evaluation`
- 关联 `workflow_stage`

前台接口：

| 接口 | 方法 | token | 说明 |
| --- | --- | --- | --- |
| `/api/tools` | GET | 不需要 | 工具列表，支持 `stageId`、`keyword` |
| `/api/tools/{id}` | GET | 不需要 | 工具详情 |
| `/api/tools/{id}/evaluations` | GET | 不需要 | 工具评分 |
| `/api/tools/recommend?stageId=1` | GET | 不需要 | 按阶段推荐工具 |

后台接口：

| 接口 | 方法 | token | 说明 |
| --- | --- | --- | --- |
| `/api/admin/tools` | POST | ADMIN | 新增工具 |
| `/api/admin/tools/{id}` | PUT | ADMIN | 修改工具 |
| `/api/admin/tools/{id}` | DELETE | ADMIN | 逻辑删除工具 |
| `/api/admin/tools/{id}/stages` | POST | ADMIN | 覆盖设置工具适用阶段 |
| `/api/admin/tools/{id}/evaluations` | POST | ADMIN | 新增或更新工具评分 |

关键字段：

- `ai_tool.name`：工具展示名。
- `ai_tool.code`：工具稳定编码，唯一。
- `official_url`：官网或使用入口。
- `logo_url`：Logo 地址。
- `description`、`price_desc`、`version_desc`：展示说明。
- `ai_tool_stage_rel.tool_id`、`stage_id`：工具适用阶段关系。
- `evaluation_dimension.name`、`code`、`sort_order`：评分维度。
- `ai_tool_evaluation.score`、`comment`：评分和说明。

展示内容怎么改：

- 工具名、官网、说明、价格、版本、Logo：改 `ai_tool`。
- 适用阶段：改 `ai_tool_stage_rel` 或调 `/api/admin/tools/{id}/stages`。
- 评分维度：改 `evaluation_dimension`。
- 某工具评分：改 `ai_tool_evaluation` 或调 `/api/admin/tools/{id}/evaluations`。

容易混淆点：

- `ai_tool_stage_rel` 是多对多关系表，一条工具可适用多个阶段。
- 评分维度不是代码常量，而是数据库数据。
- `saveToolEvaluations` 会按 `tool_id + dimension_id` 更新已有评分，不是每次都插入新行。

### 4. 提示词库模块

作用：按阶段、分类、关键词管理提示词，并支持推荐工具和复制次数统计。

数据库表：

- `prompt_template`
- `prompt_tool_rel`
- 关联 `workflow_stage`
- 关联 `ai_tool`

前台接口：

| 接口 | 方法 | token | 说明 |
| --- | --- | --- | --- |
| `/api/prompts` | GET | 不需要 | 提示词列表，支持 `stageId`、`category`、`keyword` |
| `/api/prompts/{id}` | GET | 不需要 | 提示词详情 |
| `/api/prompts/search?keyword=...` | GET | 不需要 | 搜索提示词 |
| `/api/prompts/recommend?stageId=1&toolId=2` | GET | 不需要 | 推荐提示词，`toolId` 可选 |
| `/api/prompts/{id}/copy` | POST | 不需要 | 复制次数加 1 |

后台接口：

| 接口 | 方法 | token | 说明 |
| --- | --- | --- | --- |
| `/api/admin/prompts` | POST | ADMIN | 新增提示词 |
| `/api/admin/prompts/{id}` | PUT | ADMIN | 修改提示词 |
| `/api/admin/prompts/{id}` | DELETE | ADMIN | 逻辑删除提示词 |
| `/api/admin/prompts/{id}/tools` | POST | ADMIN | 覆盖设置提示词推荐工具 |

关键字段：

- `stage_id`：提示词所属阶段。
- `title`：提示词标题。
- `code`：提示词稳定编码，唯一。
- `category`：分类。
- `content`：提示词正文，最核心展示字段。
- `input_desc`、`output_desc`、`tips`：使用说明。
- `example_input`、`example_output`：示例。
- `copy_count`：复制次数。
- `prompt_tool_rel.prompt_id`、`tool_id`：提示词推荐工具关系。

展示内容怎么改：

- 改提示词正文、说明、示例：改 `prompt_template`。
- 改推荐工具：改 `prompt_tool_rel` 或调后台关系接口。
- 前端需要更多详情字段：看 `PromptDetailVO` 和 `toDetailVO`。

容易混淆点：

- `/api/prompts/search` 必须放在 `/api/prompts/{id}` 之前理解。Spring 能按实际路径匹配，但前端不要把 `search` 当 id。
- `POST /api/prompts/{id}/copy` 是公开接口，只做计数，不要求登录。
- 列表 VO 也返回 `content`，如果前端列表不需要全文，可以后续再调整 VO。

### 3. 字段类型理解

展示用字段：

- 名称标题：`name`、`title`、`subtitle`
- 正文说明：`description`、`content`、`summary`、`tips`
- 图片/文件/链接：`logo_url`、`cover_url`、`image_url`、`asset_url`、`link_url`、`official_url`
- 展示辅助：`price_desc`、`version_desc`、`source_desc`、`author_name`

程序识别用字段：

- 主键：`id`
- 稳定编码：`code`
- 区块标识：`section_key`
- 关联 ID：`stage_id`、`tool_id`、`prompt_id`、`case_id`、`review_id`、`user_id`、`dimension_id`

管理控制用字段：

- `status`：前台是否展示，通常 `1` 展示，`0` 隐藏。
- `sort_order`：排序，越小越靠前。
- `is_deleted`：逻辑删除，`0` 正常，`1` 已删除。
- `create_time`、`update_time`：排查和管理用时间。

## 八、后续常见操作指南

### 1. 我想改首页文案

优先改数据库 `site_content`：

- 改主标题：`title`
- 改副标题：`subtitle`
- 改正文：`content`
- 改图片：`image_url`
- 改跳转：`link_url`
- 改区块顺序：`sort_order`
- 临时隐藏：`status = 0`

如果要新增新的首页结构，例如团队成员区块，可以新增新的 `section_key`，再让前端识别该 key。

### 2. 我想改工作流阶段和步骤

改 `workflow_stage` 和 `workflow_step`，或调用后台接口：

- 阶段：`/api/admin/stages`
- 步骤：`/api/admin/steps`

只改展示内容时，通常不用改代码。要加返回字段或改字段含义时，才需要改 Entity、DTO、VO、Service。

### 3. 我想改工具测评数据

根据修改内容选择表：

- 工具基础信息：`ai_tool`
- 工具适用阶段：`ai_tool_stage_rel`
- 测评维度：`evaluation_dimension`
- 评分和说明：`ai_tool_evaluation`

也可以用后台接口维护工具、阶段关系和评分。

### 4. 我想新增提示词

新增 `prompt_template` 记录，设置：

- `stage_id`
- `title`
- `code`
- `category`
- `content`
- `sort_order`
- `status`

如果要推荐工具，再新增 `prompt_tool_rel`，或调用 `/api/admin/prompts/{id}/tools`。

### 5. 我想改案例内容或案例资源

- 案例主体：改 `case_project`
- 案例资源：改 `case_asset`
- 封面图：`case_project.cover_url`
- 详情资源：`case_asset.asset_url`

如果资源只是换图片或 PDF 地址，不需要改代码。

### 6. 我想改复盘内容

- 复盘主体：改 `review_record`
- 复盘附件：改 `review_asset`
- 复盘所属用户：`user_id`
- 复盘所属阶段：`stage_id`
- 复盘关联工具：`tool_id`

当前复盘新增/修改走管理员接口，不是普通用户自助上传。

### 7. 我想让前端拿到更多字段

标准步骤：

1. 确认数据库表里有没有这个字段。
2. 如果没有，先改 SQL schema，再改 Entity。
3. 改对应 VO，加返回字段。
4. 改 Service 的 `toXXXVO` 或组装逻辑。
5. 如果新增字段也需要前端提交，改 DTO。
6. 在 Knife4j 或接口请求里验证返回。

不要直接把 Entity 返回给前端，这会让接口字段失控。

### 8. 我想新增一个接口

通常要改这些层：

1. Controller：新增 URL 和请求方式。
2. Service 接口：新增方法定义。
3. ServiceImpl：实现业务逻辑。
4. Mapper：如果 BaseMapper 不够用，再补自定义查询。
5. DTO：如果有请求体，定义请求对象和校验。
6. VO：如果返回结构不同，定义返回对象。
7. SecurityConfig：决定是否公开。
8. OpenApiConfig：决定 Knife4j 是否显示锁。
9. 必要时补 SQL 或初始化数据。

## 九、排错思路

### 1. 接口返回 401

常见原因：

- 调用了后台接口但没带 token。
- 请求头不是 `Authorization`。
- token 没有 `Bearer ` 前缀。
- token 过期或签名不对。
- 登录用户被禁用。

排查顺序：

1. 先调 `POST /api/auth/login`。
2. 拿返回的 `accessToken`。
3. 请求头设置 `Authorization: Bearer <accessToken>`。
4. 调 `GET /api/user/me` 验证 token 是否有效。

### 2. 接口返回 403

403 表示已登录但权限不够。当前最常见原因是：

- 用户角色不是 `ADMIN`。
- Controller 上有 `@PreAuthorize("hasRole('ADMIN')")`。

排查：

- 查 `sys_user.role` 是否为 `ADMIN`。
- 确认登录返回的 `user.role`。
- 确认 token 是管理员账号登录得到的。

### 3. Knife4j 里接口有锁/没锁

锁的显示由 `OpenApiConfig` 控制，实际访问权限由 `SecurityConfig` 和 `@PreAuthorize` 控制。

如果 Knife4j 显示锁但接口实际公开，检查 `OpenApiConfig` 是否把该路径加入 public 判断。

如果 Knife4j 不显示锁但接口返回 401，检查 `SecurityConfig` 是否没有放行该路径。

### 4. 数据库里有数据但前台查不到

优先检查：

- `status` 是否为 `1`。
- `is_deleted` 是否为 `0`。
- 是否传了筛选参数，例如 `stageId`、`toolId`、`keyword`。
- 关联的阶段或工具是否被禁用。

示例：

- 工具查不到：看 `ai_tool.status`、`ai_tool.is_deleted`、`ai_tool_stage_rel`。
- 提示词查不到：看 `prompt_template.status`、`is_deleted`、`stage_id`。
- 案例查不到：看 `case_project.status`、`is_deleted`。
- 首页区块查不到：看 `site_content.status`、`section_key`。

### 5. 前台能查到但后台改不了

常见原因：

- 没带管理员 token。
- 登录用户不是 `ADMIN`。
- 请求体字段缺失，DTO 校验失败。
- `code` 重复。
- 关联 ID 无效或被禁用。

排查：

1. 用管理员账号登录。
2. 确认请求头。
3. 看返回 `message`，参数校验会指出字段。
4. 查数据库唯一索引字段，例如 `code`。

### 6. 逻辑删除后数据为什么还在数据库里

当前项目使用 MyBatis-Plus 逻辑删除：

- Entity 上有 `@TableLogic`
- `application.yml` 配置逻辑删除字段 `isDeleted`
- 删除时把 `is_deleted` 从 `0` 改为 `1`

这是正常行为。前台查不到，是因为 MyBatis-Plus 会自动过滤逻辑删除数据。

### 7. code 重复导致保存失败

这些字段有唯一约束或服务层唯一校验：

- `sys_user.username`
- `workflow_stage.code`
- `ai_tool.code`
- `evaluation_dimension.code`
- `prompt_template.code`
- `case_project.code`
- `review_record.code`

解决：

- 如果只是改展示名，改 `name` 或 `title`，不要改 `code`。
- 如果确实是新数据，给一个新的稳定 `code`。

### 8. 排序不对

先看 `sort_order`，不要看 `id`。

当前常见排序：

- 阶段：`workflow_stage.sort_order ASC, id ASC`
- 步骤：`workflow_step.sort_order ASC, id ASC`
- 提示词：`prompt_template.sort_order ASC, id ASC`
- 案例：`case_project.sort_order ASC, id ASC`
- 案例资源：`case_asset.sort_order ASC, id ASC`
- 复盘：`review_record.sort_order ASC, id ASC`
- 首页内容：`site_content.sort_order ASC, id ASC`
- 获奖记录：`award_record.sort_order ASC, id ASC`

### 9. 某个页面没数据时先查哪张表

| 页面 | 先查表 | 再查表 |
| --- | --- | --- |
| 首页 | `site_content` | `award_record` |
| 阶段/流程 | `workflow_stage` | `workflow_step` |
| 工具列表 | `ai_tool` | `ai_tool_stage_rel` |
| 工具评分 | `ai_tool_evaluation` | `evaluation_dimension` |
| 提示词 | `prompt_template` | `prompt_tool_rel` |
| 案例 | `case_project` | `case_asset` |
| 复盘 | `review_record` | `review_asset` |
| 登录 | `sys_user` | 无 |

## 十、维护时的优先级建议

后续最应该先熟悉：

1. `SecurityConfig`：知道哪些接口需要 token。
2. `WorkflowController` 和 `WorkflowServiceImpl`：理解全平台阶段主线。
3. `AiToolServiceImpl`：理解阶段和工具的多对多关系。
4. `PromptServiceImpl`：理解提示词、阶段、工具三者关系。
5. `SiteServiceImpl`：理解首页聚合接口怎么给前端。

和前端同学对接时，建议先讲：

1. 所有接口统一返回 `{ code, message, data }`。
2. 公开展示接口不需要 token，后台 `/api/admin/**` 需要管理员 token。
3. 首页优先用 `/api/site/home`。
4. 工作流阶段 ID 是工具、提示词、案例、复盘的核心筛选参数。
5. 展示顺序看 `sortOrder`，不要按 `id` 排。
