# 后续升级规划

## 1. 升级原则

后续升级建议继续保持当前后端的分层风格：

- 不破坏已有公开接口路径。
- 不直接返回 `Entity`。
- 新能力优先增量新增模块。
- 管理端接口继续使用 `/api/admin/**`。
- 用户侧接口继续使用 `/api/user/**`。
- 展示接口继续使用公开 `/api/**`。
- 所有接口继续使用统一返回结构 `Result`。

## 2. 短期可做

短期目标是完成前端闭环和演示稳定性。

| 方向 | 建议内容 | 价值 |
| --- | --- | --- |
| 前端页面对接 | 对接登录、工作流执行、提示词渲染、个人中心、案例提交、后台审核 | 形成可演示的一体化网站 |
| 工作流页面体验 | 节点进度条、下一步提示、节点提示词下拉菜单 | 突出“集成一体化”优势 |
| 提示词参数表单 | 根据 `prompt_parameter` 动态生成表单 | 降低前端硬编码 |
| 最近参数回填 | 使用 `user_recent_parameter` 自动提示历史输入 | 提升个性化体验 |
| 案例审核后台 | 待审核列表、通过、驳回、审核意见展示 | 支撑用户案例沉淀 |
| 统计图表 | 使用后台统计接口做折线图、柱状图、饼图 | 支撑验收展示 |
| 部署到服务器 | 完成后端 jar、MySQL、Nginx 基础部署 | 方便内测和答辩 |
| Nginx 反向代理 | 统一前后端访问域名和接口转发 | 提升部署体验 |

## 3. 中期可做

中期目标是增强数据质量、内容管理和可运营能力。

| 方向 | 建议内容 | 价值 |
| --- | --- | --- |
| AI API 统一调用层 | 新增统一模型调用接口，封装供应商、API Key、错误处理 | 为真实 AI 生成能力打基础 |
| 文件上传与对象存储 | 接入 MinIO、阿里云 OSS 或腾讯云 COS | 支持真实案例图片和文件管理 |
| 视频资料模块 | 增加 `demo_video`、观看记录和视频评分 | 支撑演示视频、操作演示和用户反馈 |
| 更复杂的问卷系统 | 支持问卷题目、选项、多题型和结果统计 | 支撑论文分析 |
| 数据导出 | 支持统计结果、评分、问卷反馈导出 | 便于论文整理 |
| 权限角色细分 | 增加审核员、内容管理员、数据分析员等角色 | 降低管理员权限过大风险 |
| 提示词版本管理 | 为提示词增加版本、变更记录和回滚 | 提升提示词维护能力 |
| 参数选项 `optionsJson` | 为参数增加可选项、下拉枚举和默认推荐 | 提升前端表单体验 |
| 使用统计可视化图表 | 对接 ECharts 等图表库 | 提升后台可读性 |

## 4. 长期可做

长期目标是把平台从“流程辅助平台”升级为“AI 设计决策支持平台”。

| 方向 | 建议内容 | 价值 |
| --- | --- | --- |
| 多模型路由 | 根据任务类型选择不同模型或工具 | 提高生成效果 |
| 模型调用计费 | 记录 token、成本和用户额度 | 支撑真实运营 |
| 流式输出 | 使用 SSE 或 WebSocket 返回生成过程 | 提升交互体验 |
| AI 结果结构化 | 将模型输出解析为方案说明、关键词、图像提示词等结构 | 提升后续复用能力 |
| 智能推荐 | 基于用户偏好、历史参数和评分推荐流程、工具、提示词 | 提升个性化 |
| 案例知识库 | 将优秀案例沉淀为可检索知识库 | 支撑教学和复盘 |
| 数据分析仪表盘 | 面向论文和运营提供更细粒度分析 | 增强项目研究价值 |
| 团队协作 | 支持项目组、成员、协同编辑和权限控制 | 支撑真实课程或工作坊 |

## 5. AI API 统一调用层建议

当前版本未接入真实外部 AI API。后续如果要接入，建议新增独立模块，不要直接把调用逻辑写进提示词或工作流 Service。

建议模块：

```text
com.project.modules.ai
```

建议能力：

| 能力 | 说明 |
| --- | --- |
| 模型供应商配置 | 管理 OpenAI、DeepSeek、通义、豆包等供应商 |
| API Key 管理 | 加密存储，避免写入代码仓库 |
| 调用请求 DTO | 统一 prompt、model、temperature 等参数 |
| 调用记录 | 保存输入摘要、输出摘要、耗时、token、状态 |
| 错误处理 | 对超时、限流、余额不足等情况做统一异常 |
| 审计和限流 | 防止接口滥用和成本失控 |

## 6. 文件上传与对象存储建议

当前版本只保存资源 URL。后续如需真实文件上传，建议新增独立文件模块：

```text
com.project.modules.file
```

建议能力：

| 能力 | 说明 |
| --- | --- |
| 文件上传接口 | 支持图片、PDF、压缩包等 |
| 对象存储适配 | MinIO、OSS、COS 等 |
| 文件元数据表 | 文件名、大小、类型、URL、上传用户 |
| 权限校验 | 用户只能管理自己的文件 |
| 文件清理 | 删除业务数据时处理孤立文件 |

不建议直接在 `caseproject` 模块中写复杂文件上传逻辑。

## 7. 部署建议

| 项目 | 建议 |
| --- | --- |
| 后端 | Maven 打包为 jar，使用 systemd 或 Docker 运行 |
| 数据库 | MySQL，先执行完整 SQL 脚本 |
| 反向代理 | Nginx 转发 `/api/**` 到后端服务 |
| 前端 | 静态资源由 Nginx 托管 |
| 日志 | 保留后端运行日志和异常日志 |
| 配置 | 数据库密码、JWT 密钥等放在环境变量或服务器配置中 |

## 8. 推荐优先级

| 优先级 | 内容 |
| --- | --- |
| P0 | 前端对接工作流执行、提示词渲染、用户案例审核 |
| P1 | 服务器部署、Nginx 反向代理、统计图表 |
| P2 | 文件上传与对象存储、视频资料模块 |
| P3 | AI API 统一调用层、提示词版本管理 |
| P4 | 多模型路由、智能推荐、团队协作 |
